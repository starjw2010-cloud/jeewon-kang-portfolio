# Customer Success Review Framework

고객 프로젝트와 SaaS 운영 경험을 바탕으로 정리한 점검 프레임입니다. 고객별 목표와 계약 범위에 맞춰 항목을 선택하며, 모든 고객에게 동일하게 적용했다는 의미는 아닙니다.

| 영역 | 확인할 질문 | 남길 근거 | 다음 행동 |
|---|---|---|---|
| Business Goal | 도입으로 어떤 업무를 개선하려는가? | 고객 목표, 대상 업무, 의사결정자 | 우선순위와 성공 기준 합의 |
| Delivery | 현재 범위와 일정에서 막힌 지점은 무엇인가? | 마일스톤, 이슈, 외부 의존성 | 담당자·대응 계획·확인 시점 정리 |
| Adoption | 어떤 사용자가 어떤 업무에서 활용하는가? | 활성 사용자, 사용 기능, 기간, 인터뷰 | 역할별 교육과 업무 흐름 개선 |
| AI Quality | 답변의 근거와 접근 권한은 적절한가? | 평가 사례, 오류 유형, 출처, 권한 | 사용 범위 조정과 검증 과제 설정 |
| Risk | 기술·보안·사용·의사결정 위험이 있는가? | 발생 신호, 영향 범위, 조치 상태 | 조기 공유와 담당 조직 연결 |
| Renewal | 유지할 가치와 갱신 조건은 무엇인가? | 사용 현황, 구매 조직, 예산·계약 일정 | 갱신 논의와 선행 과제 확인 |
| Expansion | 해결되지 않은 업무와 내부 수요가 있는가? | 신규 요구, 추진 주체, 성공 기준 | BD·기술 담당자와 제안·PoC 구체화 |
| Feedback | 반복되는 문제를 어디에 반영할 것인가? | 사례, 재현 조건, 고객 영향 | 서비스 개선 또는 제품 검토 과제로 전달 |

## Metric Definitions

사용자 수에는 대상·활성·응답자 중 무엇인지, 사용량에는 측정 기간과 기능 범위를 기록합니다. 교육 만족도와 실제 업무 활용률을 구분하고, 제품 사용량과 계약 전환의 인과관계를 단정하지 않습니다.

PoC 점검에서는 업무 사용자와 지원 인력·미사용 계정을 구분합니다. 공식 운영 기간과 종료 이후의 관찰 기간을 나누고, AI 템플릿 제공 수와 고객의 실제 제작·실행을 별도로 봅니다. 메시지 작성 위치와 열람 위치도 같은 지표로 취급하지 않습니다. [적용 사례](../case-studies/11-ai-adoption-review.md)

## Decision Record

```text
고객 목표 / 확인한 사실 / 남은 문제
→ 결정: 유지 · 개선 · 확장 · 보류 · 종료
→ 다음 행동 / 담당자 / 확인 시점
```
