# Career Knowledge Base — 경력을 직무별로 재사용하는 기준

기준일: 2026-10-09 · 공개용 경력 지식베이스

강지원의 경험은 고객 문제를 사업과 서비스로 구체화하고, 파트너·기술·고객 조직과 함께 실행해 도입 이후의 운영과 확장으로 연결한 흐름입니다. 직무에 따라 강조점은 바꾸되 수행 사실과 성과의 범위는 유지합니다.

## 읽는 순서

1. [통합 경력 원장](MASTER_PROFILE.md): 경력의 공통 정체성·업무 범위·책임
2. [역량·사례 매핑](CAPABILITY_MATRIX.md): 채용요건에 맞는 사례 선택
3. [직무별 지원 가이드](APPLICATION_PLAYBOOK.md): 지원서·면접 조합
4. [근거 관리표](EVIDENCE_REGISTER.md): 확인 수준·미확인 결과·표현 제한
5. [업데이트와 인수인계](MAINTENANCE.md): 여러 대화와 문서 간 정보 유지
6. [사례 입력 템플릿](../templates/experience-card.md): 새로운 경험 추가

## 정보의 역할

| 위치 | 역할 | 갱신 방식 |
|---|---|---|
| 이 GitHub 저장소 | 공개 가능한 경력 해석·사례·직무별 설명의 기준 | 새 사실을 근거표와 원장에 반영하고 관련 사례를 수정 |
| Google Drive 경력 원장·제안서·포트폴리오 | 세부 증빙과 원본 산출물 | 현재 버전·기준일을 확인한 뒤 인용 |
| 업무 Slack 기록 | 당시 행동·협의·후속 조치의 근거 | 메시지와 스레드 전체의 맥락을 비공개로 확인 |
| 개별 지원서 | 특정 공고에 맞춰 선택한 경력의 스냅샷 | 사용한 사례·근거 버전과 제출일을 별도 기록 |
| AI 대화 | 조사·초안·가설을 만드는 작업 공간 | 새 사실과 정정을 원장에 옮긴 뒤 재사용 |

자동 동기화는 설정되어 있지 않습니다. 공개 저장소에는 내부 원문 링크, 고객별 견적·과금 조항, 지원 현황·연봉·개인 연락처를 넣지 않습니다. 내부 원자료를 공개하기 위한 공간이 아닙니다.
