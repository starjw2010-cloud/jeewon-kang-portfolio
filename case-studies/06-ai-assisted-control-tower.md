# Case 06. SemiFlow — AI-assisted Operations Control Tower

**Status:** 개인 R&D / Synthetic Sandbox · 2026.10.07 점검 자료 기준

**더 자세히:** [제품 판단·AI 구조·검수·운영 전환 상세 사례](../public-projects/semiflow-deep-dive.md)

## Context
제조 운영 담당자가 주문, 생산, 자재, 출하 정보를 연결해 납기 위험을 조사하고 경영진에게 설명하는 과정을 다룬 프로젝트입니다.

합성 제조 데이터를 사용해 **위험 확인 → 근거 조사 → AI 설명 → 보고서 검토**라는 업무 흐름을 구체화했습니다. 실제 고객의 유료 구축·운영 실적과는 별도로 진행한 AI-assisted R&D입니다.

## Problem & Success Criteria
여러 업무 시스템에 정보가 흩어져 있으면 위험 원인을 찾고, 사실과 해석을 구분해 보고하는 데 어려움이 생깁니다. 다음 기준으로 기능과 검증 범위를 정리했습니다.

| 업무 질문 | 수용 기준 |
|---|---|
| 어떤 주문을 우선 확인해야 하는가? | 같은 데이터로 위험을 다시 계산할 수 있고 원인을 확인할 수 있다. |
| AI의 설명을 믿을 수 있는가? | 확인된 사실·출처, AI 해석, 미확인 정보를 구분한다. |
| 누가 어떤 정보를 볼 수 있는가? | 사용자 권한과 조직·주문 범위를 조회 및 검색에 적용한다. |
| 경영진에게 어떻게 전달할 것인가? | 조사 근거를 유지한 보고서를 검토하고 PDF로 인쇄할 수 있다. |

## My Role
제품 Owner로서 문제와 요구사항, 작업 범위, 수용 기준을 제시하고 AI Coding Agent에 구현·수정 작업을 요청했습니다. 결과는 요구사항 충족 여부, 검증 기록, 남은 제약을 기준으로 검토했습니다.

코드 구현은 AI-assisted 방식으로 진행했습니다. 제 기여는 업무 흐름 정의, 우선순위와 제약 설정, 변경 요청과 결과 검토를 중심으로 설명합니다.

프로젝트는 범위별 구현, 독립 검토, 자동검증과 변경 통합을 거쳐 실행 환경을 확인하는 방식으로 관리합니다. 제품 기능이 구현된 상태와 고객 업무에 도입할 준비가 된 상태를 나누어 판단합니다.

## Key Decisions

### 1. 운영 사실과 AI 설명의 역할 분리
위험 점수와 운영 수치는 정해진 데이터·계산 규칙에서 나오도록 했습니다. AI는 허용된 근거를 찾아 설명과 대응 초안을 제공합니다.

추가 업무 맥락을 사용하는 답변 경로에서는 모델이 선택한 사실 ID를 서버가 검증하고, 해당 원문과 출처로 답변을 구성합니다. 자연어 해석에는 여전히 오류 가능성이 있어 사람의 검토를 유지합니다.

### 2. 질문에 필요한 근거를 허용된 범위에서 검색
주문·고객, 생산, 자재, 입고, 출하·물류 중 질문에 필요한 맥락을 검색하도록 구성했습니다. 검색 결과는 해당 조직과 주문, 데이터 버전에 맞는지 확인합니다.

근거 누락, 오래된 정보, 충돌, 검색 실패를 정상 결과로 바꾸지 않고 사용자에게 드러내도록 했습니다.

### 3. 조사 결과를 의사결정 자료로 연결
한국어 화면에서 주문을 선택하고 질문·후속 질문을 거쳐, 핵심 요약·현황·위험·대응 제안·근거를 담은 임원 보고서를 검토할 수 있도록 했습니다.

보고서는 기존 조사 답변을 활용하며, 확인된 수치와 AI 분석 의견을 구분합니다. 주문이나 조사 결과가 바뀌면 오래된 보고서가 그대로 사용되지 않도록 검증합니다. PDF는 브라우저 인쇄 기능을 사용합니다.

## Current Scope & Evidence

| 범위 | 2026.10.07 기준 확인 내용 |
|---|---|
| 운영 조회와 위험 분석 | 합성 데이터 기반 도메인·위험 계산과 한국어 Web 구현 |
| 업무 데이터 | 36개월·36,000건의 합성 주문과 생산·자재·입고·출하 데이터. 실제 고객 처리량과 구분 |
| AI 조사 | 읽기 전용 조사, 범위가 제한된 검색, 답변 검증, 후속 질문 구현 |
| 보고서 | 미리보기·PDF 인쇄 구현, 테스트용 데이터의 인쇄 검토 기록 |
| 품질 검증 | Backend·Web·PostgreSQL 통합 자동검증 성공 기록 |
| 실제 운영 | 일부 Sandbox 배포·Demo 기록 존재. 현재 가동 상태와 최신 AI 답변에서 보고서까지의 전체 동작은 별도 확인 필요 |

주요 기술 범위는 FastAPI, Next.js, PostgreSQL, Vector Retrieval, 로컬 모델 Adapter, 인증·권한·감사 및 자동검증입니다. 코드와 검증 기록의 존재를 상용 운영 완료로 해석하지 않습니다.

## Boundaries & Next Step
- 데이터와 개발 범위는 합성 데이터 기반 Sandbox입니다.
- 현재 Agent는 조회·분석·초안·추천 범위이며, 외부 업무 시스템을 자율적으로 변경하는 기능은 후속 범위입니다.
- 실제 고객의 시간 절감률, 매출 효과, 운영 SLA는 측정하지 않았습니다.
- 다음 확인 과제는 실제 실행 환경의 상태, 전체 업무 흐름, 실패 시 사용자 경험, 복구 절차와 운영 인수 기준입니다.

## Relevance to Enterprise Customer Success
AI 도입을 논의할 때 업무 문제를 사용 시나리오와 수용 기준으로 구체화하고, 기술팀과 데이터·권한·검증 범위를 합의하는 데 적용할 수 있는 경험입니다. 특히 Demo의 기능 확인 이후 실제 운영으로 넘어가기 위해 무엇을 더 확인해야 하는지 설명하는 역량을 보여 줍니다.

## Lesson
AI 기능의 가치는 **사용자가 어떤 판단을 할 수 있게 되었는지, 그 판단의 근거가 무엇인지, 운영 전 확인할 조건이 무엇인지**까지 연결해 설명해야 합니다.
