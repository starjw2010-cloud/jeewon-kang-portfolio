# Slack 프로젝트의 수행 관리와 운영 설계

계약한 범위를 실행하려면 고객의 선행 작업, 공급사 승인, 현업의 확인과 운영 인계가 함께 움직여야 합니다. 서로 다른 고객 프로젝트의 일정표·작업현황·교육 부록에서 확인되는 수행 방식을 정리했습니다.

## 1. 기업 통합 프로젝트 — 작업과 의사결정을 같은 일정에서 관리

2025년 기업 협업환경 통합 일정표에는 작업별 담당자, 계획 시작·종료일, 실제 종료일, 상태와 진행률을 함께 기록했습니다. 강지원이 담당한 항목에는 통합 작업 가이드, 공동 이관, 공급사 내보내기 승인, 관리자 가이드, 교육자료 전달과 사용자·관리자 교육이 포함됩니다.

| 수행 영역 | 연결한 선행 작업과 확인 |
|---|---|
| 통합 준비 | 고객의 소유자 변경·채널 목록 수집과 컨설턴트의 작업 안내 |
| 이관 | 공급사 승인, Workspace별 실행 순서와 공동 작업 담당 |
| 사용자 준비 | 관리자 가이드, 전사 안내자료와 사용자·관리자 교육 |
| 오픈 확인 | 고객 담당자의 구성원 초대, 리더 확인과 작업 완료 확인 |

기술 작업이 끝나는 시점과 고객이 새 환경을 사용할 준비가 되는 시점을 함께 관리했습니다. 일정표는 진행 중 시점의 기록이므로, 남아 있는 확인 항목까지 완료 처리한 문서로 해석하지 않습니다. 최종 수행 결과는 [Case 03](../../case-studies/03-incident-and-escalation.md)에 정리했습니다.

## 2. 별도 통합 프로젝트 — 계약 범위를 실제 사용과 권한에 맞추기

2026년의 별도 이관 프로젝트에서는 사전조사·견적·고객 확인 시트·앱 처리 목록·이관 결과보고를 연결했습니다. 견적의 공급자 및 고객 문의 담당자로 본인이 명시되어 있습니다.

- **고객이 결정할 것:** 대표 계정, 계속 사용할 외부 연결과 자동화, 유지할 앱을 확인하도록 요청했습니다.
- **컨설턴트가 수행할 것:** 확인된 범위의 데이터 이관, 계정 대응 관계와 채널 구성 검토, 가능한 자동화의 이전 작업을 정리했습니다.
- **고객 권한이 필요한 것:** 외부 서비스 로그인이나 자체 앱 재배포가 필요한 항목을 따로 분류했습니다.
- **추가 협의할 것:** 범위 밖의 추가 작업·재작업과 선행 조건 변경을 별도 협의 대상으로 명시했습니다.

작업 상태도 구분했습니다. 게시된 워크플로우는 현업 동작 확인을 남겨 두고, 연결 설정이 필요한 항목은 담당자 조치 대상으로 안내했습니다. 일부 Workspace의 결과보고에는 계정 병합·개별 보존·과거 메시지 보존을 구분하고, 채널의 공개 범위를 별도로 기록했습니다.

민감 채널 처리 안내에는 이관 방식별 정보 노출과 중복 생성의 영향을 비교하고, 후속 정리와 고객 확인이 필요한 내용을 담았습니다. 확인 서명이 비어 있는 안내문은 **위험 설명과 의사결정 준비의 근거**로만 사용합니다.

이 자료들은 수행 중의 고객 확인과 작업 인계를 보여 줍니다. 일부 데이터의 처리 결과를 전체 프로젝트 검수 완료나 모든 연동의 정상 동작으로 확대하지 않습니다. [사전조사와 작업 관리 샘플](migration-readiness.md)

## 3. 대학 연구조직 — 관리자 교육에서 운영 구조의 선택까지

관리자 교육 부록에서는 공용 공간, 제한된 논의 공간, 개별 연구실의 공간을 어떻게 나눌지 대안을 비교했습니다. 구성원 합류와 연구실 신설 때 관리자가 해야 할 작업, 정보 검색과 접근 범위를 함께 고려했습니다.

| 설계 항목 | 고객에게 확인할 운영 결정 |
|---|---|
| 협업 공간 | 전체 공유와 제한된 논의, 개별 조직의 경계 |
| 관리 책임 | 조직 정책, 공간 운영, 계정·역할 관리의 담당 |
| 외부 협업 | 참여 목적에 맞는 접근 범위와 계정 종료 시점 |
| 운영 방식 | 자동화할 수 있는 작업과 관리자가 직접 처리할 작업 |

이는 고객별 **운영 권고안과 교육 설계**입니다. 권고한 구조 전체가 실제 배포되었다는 의미는 아닙니다. [역할별 교육과 업무 적용](role-based-enablement.md)

## 자료와 기여 범위

2025년 기업 통합 WBS, 2026년 별도 이관의 견적·확인·상태·결과 자료, 대학 관리자 교육 부록을 대조했습니다. 고객명·계정·자산 목록·상업 조건은 제거했고, 서로 다른 프로젝트의 결과는 합산하지 않았습니다. 제품의 현재 이관·보안 기능을 안내하는 문서가 아니라 당시 수행과 의사결정 방식의 사례입니다.
