# Slack Business Development — 도입에서 서비스·고객 확장까지

**역할:** Slack 사업 리드·컨설팅 · **소속:** i2MAX

사내 Slack 도입을 제안하고 승인 이후 내부 도입 PM을 맡았습니다. 이후 Slack 사업을 전개하며 고객의 라이선스 도입에 온보딩·교육·이관을 연결하고, 고객별 요구를 수행 범위와 후속 제안으로 구체화했습니다.

담당한 범위는 고객 미팅과 제안, 도입·교육 수행, 사용 결과 점검, 계약·갱신 지원입니다. 영업·기술 담당자 및 공급사와 협업하면서 고객이 구매할 범위와 실제로 제공할 작업을 맞췄습니다.

## 1. 고객의 도입 조건에서 제안을 시작

고객마다 기존 협업환경, 구매 주체와 필요한 지원이 달랐습니다. 고객 제안에서는 업무 문제와 도입 조건에 따라 범위와 순서를 조정했습니다.

사업 소개자료에는 의사결정권자 확인, 예산 확보 여부, 파일럿 부서와 내부 추진 담당자(Champion)를 착수 조건으로 정리했습니다. 사용할 기능과 함께 고객이 실제로 결정을 내리고 도입을 이어갈 준비가 되어 있는지를 확인하는 제안 기준입니다.

| 고객 상황 | 확인한 문제·조건 | 제안에 연결한 내용 |
|---|---|---|
| 협업 도구를 처음 도입하는 조직 | 대상 사용자, 업무 목적, 관리자와 초기 정착 지원 | 라이선스와 사용자·관리자 온보딩 |
| 여러 협업환경이 분산된 기업 | 통합 대상, 계정·데이터·외부 협업, 도입 일정 | 단계 도입 또는 통합 도입, 이관과 교육 범위 |
| 교육으로 활용을 시작하는 대학 | 수강 대상, 담당 조직, 기존 교육사업과 예산 책임 | 특강·역할별 교육과 반복 프로그램 제안 |
| AI·CRM 활용을 검토하는 기업 | 검증할 업무, 데이터·권한, 보안 요구와 운영 주체 | 업무 시나리오, Demo·PoC, 기술 확인과 결과 점검 |

대학 사업단 제안에서는 고객 피드백에 따라 기관 전체의 확장 구상에서 사업단이 직접 추진할 작은 검증 과제로 범위를 조정했습니다. [제안 재설계 사례](../../case-studies/12-feedback-led-proposal.md)

라이선스 범위도 사용 현황에서 출발했습니다. 2023년 본인이 공급사 담당자로 명시된 주문서에는 분산된 무료 Workspace의 활성 사용자를 조사해 초기 계약 수량을 산정하고, 추가 사용과 갱신 기준을 안내한 내용이 남아 있습니다. 이용자 규모와 구매 조건을 맞추는 계약 담당 경험입니다.

고객별 시스템 연계 제안에서는 기존 CRM·분석 도구와 연결할 수 있는 업무, 별도 앱이 필요한 업무, 외부 시스템 API 협의가 선행되어야 하는 업무를 나눴습니다. 고객이 확인할 조건과 공급사 협의 항목을 구분해 단계별 도입안을 제시했습니다. 해당 연계안은 제안 산출물이며, 모든 기능의 구축·계약 완료를 의미하지 않습니다.

업종별로는 사용자가 실제로 처리할 업무를 제안 시나리오로 구체화했습니다.

| 제안 대상 | 업무와 도입 조건을 설명한 방식 |
|---|---|
| 소비재 기업 | 기존 문서 도구의 역할을 유지하면서 협업·검색을 연결하고, 대상 부서와 전환 일정에 따라 단계 도입·통합 도입을 비교 |
| 서비스 기업 | 공식 결재·근태 기록은 기존 시스템에 두고, 요청 상태와 담당자 안내를 협업 공간에서 보완. 고객의 범위 확인과 외부 공급사의 API 협의를 분리 |
| 뷰티 기업 | 글로벌 캠페인 승인, 제품 변경·납기와 담당자 인계를 업무 흐름으로 설명 |
| 금융 기업 | 경영관리·IT 담당자의 보고, 문의와 조치 과정을 역할별 시나리오로 구성 |

각 자료에 본인이 담당자로 명시되어 있습니다. 여기서 보여 주는 기여는 **고객의 업무를 도입안과 설명 시나리오로 바꾼 것**이며, 제안서의 예상 절감률·처리시간·계약 증가는 실제 성과로 사용하지 않습니다.

## 2. 라이선스에 도입 서비스를 연결

고객이 필요한 작업을 선택하고 제공 범위를 이해할 수 있도록 온보딩·교육·이관·운영지원을 서비스 구성으로 정리했습니다.

| 사업 구성 | 고객이 필요로 한 것 | 담당한 업무와 확인된 범위 |
|---|---|---|
| 라이선스 도입·갱신 | 사용자와 구매 조직에 맞는 이용 범위 | 수요 확인, Trial·제안·유료 전환·갱신 지원 |
| 온보딩·교육 | 초기 환경과 사용자·관리자의 정착 | 채널 구성, 역할별 교육, 단계별 수행과 인계 |
| Migration·통합 | 분산된 계정·대화·협업환경 정리 | 사전조사, 이관 계획·공동 실행, 예외 대응과 검증 |
| 후속 운영지원 | 도입 이후 반복되는 계정·SSO·앱 문의 | 지원 범위, 제공 방식과 작업량 산정 기준 기획 |
| 업무 활용 확장 | 기존 도구·데이터와 연결할 새로운 과제 | 업무 PoC, AI 활용 시나리오와 후속 제안 |

온보딩은 실제 고객 프로젝트에서 단계별로 수행했습니다. 운영지원 상품은 반복 요청을 서비스로 정리한 기획 결과이며, 새로 제안한 연동·확장 과제의 계약 상태는 각각 구분합니다.

전사 도입용 서비스 소개서에서는 **초기 관리자 역량 이전 → 정기 거버넌스 점검 → 운영 최적화 지원**을 구분했습니다. 해당 서비스 패키지의 기본 범위와 추가 계약 범위에 작업·수행 방식·산출물을 연결해, 도입 이후 고객이 어떤 지원을 구매할 수 있는지 설명했습니다. [서비스 구성과 산출물](../slack-delivery-and-enablement.md)

## 3. 교육을 초기 정착과 후속 사업의 접점으로 활용

교육은 고객이 업무에 도구를 적용해 보고 추가 요구를 설명할 수 있는 접점이었습니다. 대상별 커리큘럼을 구성하고, 현장에서 확인한 과제를 다음 논의로 연결했습니다.

| 접점 | 수행한 활동 | 사업상 이어진 단계 |
|---|---|---|
| 도입 전 제안·시연 | 고객의 업무를 설명할 시나리오와 교육 범위 구성 | 도입 범위와 필요한 지원 협의 |
| 초기 온보딩 | 사용자·관리자의 과제를 나누고 실제 업무에 적용하도록 안내 | 고객이 구매한 도입·교육 범위 수행 |
| 기존 고객 교육 | 현장에서 연구장비 관리 등 추가 업무 요구 확인 | 별도 업무 PoC 설계·수행 |
| 후속 과제 협의 | AI 유학생 지원 등 새로운 요구를 정리하고 피드백 반영 | RFP 초안·제안 자료 작성 |

대학 고객에서는 교육 이후 연구장비관리 PoC와 별도 AI 지원 과제 제안으로 논의를 확장했습니다. 교육 수행, PoC 수행, 후속 제안은 각자의 결과를 가진 업무로 관리했습니다. [고객 확장 사례](../../case-studies/08-account-expansion.md)

별도의 교육 파트너십 제안에는 팀의 Slack 담당으로 참여해, 특강 이후 반복 운영할 수 있는 프로그램의 대상·제공 범위·운영 책임을 구체화했습니다. 학생·기업 관계자·실무자별 과정을 나누고, 기업 관계자 과정은 업무 체험에서 조직 적용안과 후속 상담으로 이어지도록 제안했습니다.

교육 제공자의 강의·평가 역할과 고객 조직의 승인·모집·행정·예산 역할을 구분했습니다. 참여·이수·산출물·만족도·도입 의향 등을 파일럿 검토 항목으로 제시하고, 결과에 따라 확대하거나 다시 설계하는 조건을 포함했습니다. 이 반복 프로그램은 제안 단계의 사업 기획입니다.

## 4. 제안 이후 수행과 고객 관계까지 연결

- **기술 검토:** 현업의 업무 요구와 IT·보안의 조건을 모아, Demo·PoC에서 확인할 범위를 정했습니다.
- **수행 조율:** 고객 담당자·동료 컨설턴트·공급사와 일정, 권한, 이관 및 장애 조치를 맞췄습니다.
- **사용 결과 점검:** 사용 지표와 고객 피드백을 정리해 유지·개선·확장 또는 종료 논의를 지원했습니다.
- **계약 관계 관리:** 라이선스 전환·갱신과 추가 교육 제안을 별도로 다루고, 같은 기관 안에서도 구매 주체와 사용 범위를 구분했습니다.
- **사업 운영:** CRM에서 사업 항목·영업 단계·기존 계정의 활동 이력을 추출해 사업 검토와 후속 접촉 준비를 지원했습니다. 본인 명의로 생성한 보고서가 근거이며, 보고서에 담긴 전체 계정을 개인 담당 고객 수로 집계하지 않습니다.
- **공급사 협업:** 공급사 AE·BDR·SE와 정기적으로 고객·산업별 기회를 조율하고, 고객의 협업 도구 요구와 교육 프로그램 방향을 검토했습니다.

작업 일정표에는 고객의 선행 작업과 공급사 승인, 본인·동료의 수행, 사용자 교육과 고객 확인을 함께 기록했습니다. 별도 이관 견적에서는 고객이 먼저 결정할 항목, 외부 계정 권한이 필요한 작업, 추가 협의 범위를 구분했습니다. [수행 관리와 운영 설계](delivery-and-governance.md)

## 근거와 기여 범위

2023년 담당자 명시 주문서, 2024–2025년 본인 생성 CRM 보고서·업무기록과 수행 일정표, 2026년 Slack 사업·서비스 소개자료와 고객별 제안·이관 자료, 기존 경력기록을 대조했습니다. 사내 도입과 초기 사업 경위는 강지원 명의의 사업 소개자료에 정리된 이력이며, 개별 수행·계약 결과는 연결된 고객 사례의 범위입니다. 회사 전체 수주·매출·목표를 개인 실적으로 합산하지 않았습니다.
