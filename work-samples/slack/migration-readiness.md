# Slack Migration Readiness — 사전조사와 의사결정 시트

**공개용 재구성 샘플 · 조사·작업 준비 문서 · 이관 완료 보고서와 구분**

여러 Workspace를 통합할 때에는 데이터와 함께 사용자 계정, 외부 협업, 업무 자동화의 처리 방향을 결정해야 합니다. 이 샘플은 비공개 사전조사 양식 2종과 고객 확인용 작업현황 자료 1종에서 확인한 질문과 분류 방식을 재구성했습니다.

핵심은 **관리자 자료로 현황을 먼저 채우고, 고객에게 필요한 판단과 확인만 요청하는 것**입니다. 기존 [대규모 이관 사례](../../case-studies/02-large-scale-migration.md)가 수행 결과를 설명한다면, 이 문서는 실행 전에 어떤 항목을 확인하고 누구의 결정을 기다려야 하는지 보여 줍니다.

## 1. 원자료에서 확인한 업무 설계

- Workspace·사용자·외부 연결·앱과 워크플로우·기타 자산을 나누어 조사합니다.
- 관리자 자료로 확인할 수 있는 현황과 고객이 결정해야 하는 항목을 구분합니다.
- 동일인의 다른 계정, 동명이인, 중복 자동화, 담당자 미지정 자산 등 예외를 먼저 표시합니다.
- 외부 연결의 기존 답변을 보존하면서 최근 활동이나 다른 Workspace의 유지 결정과 맞지 않는 항목을 재확인합니다.
- 서드파티 앱과 자체 개발 앱·봇을 구분해 재설치, 재구축, 소스·개발자 확인을 별도 검토합니다.

아래의 담당 역할, 상태, 기한과 검증 기록 형식은 이 구조를 설명하기 위해 추가한 공개용 설계입니다. 실제 프로젝트에서 해당 절차가 모두 완료되었음을 뜻하지 않습니다.

## 2. 사전조사 시트 구성

| 조사 영역 | 먼저 정리할 현황 | 고객에게 확인할 결정 | 작업 계획에 반영할 내용 |
|---|---|---|---|
| Workspace | 현재 플랜, 소유자 역할, 사용자·게스트 범위, 데이터 규모 | 통합 대상과 운영 책임 | 플랜·권한·선택한 도구에 따른 이관 가능 범위와 승인 의존성 |
| 사용자 계정 | 소속 Workspace, 계정 대응 관계, 재직·활성 상태 | 대표 계정, 병합 여부, 각각 보존할 예외 | 계정 매핑과 검증 대상 |
| 외부 협업 | 외부 연결의 유형, 활동 현황, 관련 Workspace | 유지·정리·추가 확인, 연락 담당 | 연결별 처리 계획과 상대 조직 협의 |
| 워크플로우 | 용도, 관리자, 실행 범위, 중복 여부, 사용자 정의 단계 | 실제 사용 여부와 유지할 업무 | 이관 방식·재구축 여부와 업무 담당 |
| 설치 앱 | 설치 범위, 중복 설치, 업무 용도 | 통합 후 사용 여부 | 설치·설정·연동 확인 항목 |
| 자체 개발 앱·봇 | 관리자, 관리 상태, 소스·개발자 확인 가능 여부 | 계속 사용할 기능과 책임자 | 재구축·재배포 검토와 기술 의존성 |
| 기타 자산 | 사용자 그룹, 기본 채널, 이모지, Canvas·List | 유지할 자산과 우선순위 | 별도 이관·재설정·검토 항목 |

공개본에는 자산의 실제 명칭이나 식별값을 싣지 않습니다. 실제 업무 시트에는 필요한 정보를 접근이 제한된 자료에 기록하고, 고객이 답할 칸과 참고용 현황을 구분합니다.

이관 가능 여부와 재설정 방식은 대상 플랜, 도구와 현재 지원 조건을 확인해 확정합니다. 이 문서의 질문 목록만으로 특정 자산의 자동 이관 여부를 단정하지 않습니다.

## 3. 고객에게 요청할 질문을 좁히는 방법

| 상황 | 확인 질문 | 판단을 남기는 방식 |
|---|---|---|
| 계정 정보가 서로 다름 | 같은 사람인지, 어떤 계정을 기준으로 할지, 각각 보존할 이유가 있는가? | 병합·개별 보존·추가 확인과 결정 근거 |
| 이름이 같지만 다른 사람일 수 있음 | 이름 외의 계정·조직 정보로 구분했는가? | 확인 전 병합 대상에서 보류 |
| 이름이 비슷한 워크플로우가 여러 개임 | 실제로 사용하는 것은 무엇이며, 업무 담당자는 누구인가? | 사용·미사용·확인 필요와 담당 역할 |
| 외부 연결의 처리 방향이 비어 있음 | 최근 활동과 현재 협업 필요를 확인했는가? | 유지·정리·추가 확인과 연락 담당 |
| 같은 외부 조직이 여러 Workspace에 연결됨 | 한 곳의 유지 결정이 다른 연결에도 적용되는가? | 연결별 결정을 따로 기록 |
| 자체 개발 봇의 관리자가 없거나 오래됨 | 현재 사용하는가, 소스와 개발 담당자를 확인할 수 있는가? | 재구축 검토와 미확인 의존성 |

중복, 오래된 생성일, 활동 부족과 담당자 부재는 **확인 우선순위의 신호**로 사용합니다. 사용 종료나 삭제 결정을 자동으로 대신하지 않습니다.

## 4. 리스크·담당·의존성 관리 예시

아래 행은 실제 고객 기록을 옮긴 것이 아닌 설계 예시입니다. 담당은 개인명 대신 역할로 표시하며 실제 프로젝트에서 지정합니다.

| 검토 항목 | 리스크 | 담당 역할 예시 | 선행 확인·의존성 | 확인 기록 |
|---|---|---|---|---|
| 계정 대응 관계 | 다른 사람의 계정을 합치거나 같은 사람의 계정을 중복 생성 | 고객 사용자 정보 담당 + Workspace 관리자 | 재직 상태, 대표 계정, 보존 예외 결정 | 최종 매핑과 예외 목록의 확인 여부 |
| 외부 연결 처리 | 계속 필요한 협업 연결 누락 | 고객 협업 담당 + 상대 조직 담당 | 유지 결정과 연락 담당 확보 | 연결별 처리 계획과 후속 접속·협업 확인 |
| 핵심 워크플로우 | 데이터는 옮겼지만 업무 자동화가 작동하지 않음 | 업무 담당 + 구축 담당 | 사용 여부, 사용자 정의 단계, 재구축 방식 | 합의한 업무 시나리오의 동작 확인 |
| 자체 개발 앱·봇 | 원본 코드나 관리 담당자 부재로 후속 작업 지연 | 개발·운영 담당 | 소스·개발자·관리 상태 확인 | 필요한 작업과 미해결 의존성 |
| Workspace의 이관 조건 | 승인·접근 권한·지원 범위 미확인으로 실행 일정 변경 | Workspace 소유자 + 이관 담당 | 현재 플랜, 권한, 이관 도구와 범위 | 확인한 범위와 제외·추가 검토 항목 |

추적할 공통 열:

| 항목 | 기록 내용 |
|---|---|
| 상태 | 미확인 / 고객 결정 대기 / 작업 계획 반영 / 검증 대기 / 검증 확인 / 보류 |
| 담당·기한 | 다음 답변 또는 작업을 맡은 역할과 합의한 날짜 |
| 선행 조건 | 다음 단계 전에 필요한 결정·자료·권한 |
| 검증 방법 | 무엇을 어떤 범위에서 확인할지 |
| 확인 기록 | 확인일, 확인 역할, 결과와 남은 예외 |

‘유지하기로 결정함’, ‘작업을 계획함’, ‘작업 후 동작을 확인함’은 각각 별도 상태로 기록합니다.

## 5. 실행 전과 실행 후의 확인 목록

다음은 공개 샘플용 체크리스트입니다. 체크되지 않은 항목을 완료 실적으로 해석하지 않습니다.

**실행 전**

- [ ] 통합 대상과 제외 대상을 구분했다.
- [ ] 계정 병합·개별 보존·동명이인 예외를 고객과 확인했다.
- [ ] 외부 연결별 유지·정리 결정과 연락 담당을 확보했다.
- [ ] 실제 사용하는 자동화와 앱을 선별하고 담당을 정했다.
- [ ] 자체 개발 자산의 소스·개발자 등 미해결 의존성을 기록했다.
- [ ] 이관 방식, 선행 조건과 검증할 범위를 작업 계획에 반영했다.

**실행 후 확인을 위해 준비할 것**

- [ ] 계정·채널·메시지 등 대조할 항목과 비교 범위를 정한다.
- [ ] 유지 대상으로 정한 외부 협업과 업무 자동화의 확인 항목을 정한다.
- [ ] 제외·보류·재작업 항목과 후속 담당을 별도로 기록한다.
- [ ] 특정 데이터의 이관 결과와 전체 업무의 정상 사용 여부를 나누어 보고한다.

## Source Basis & Scope

2026년 7월의 비공개 마이그레이션 사전조사 양식 2종과 고객 확인용 작업현황 자료 1종을 읽고, 2026-10-07 공개용으로 재구성했습니다. 자료에서 확인한 것은 조사 항목, 고객 확인 요청, 일부 답변·예외와 후속 판단 구조입니다. 문서 제목의 ‘작업현황’을 이관 완료나 검수 완료의 근거로 사용하지 않았습니다.

원문의 고객·사용자·외부 조직·자산 식별정보, 수량과 원본 링크는 포함하지 않았습니다. 이 샘플의 구성만으로 원자료의 단독 작성 기여, 실제 적용 범위나 완료 성과를 주장하지 않습니다.
