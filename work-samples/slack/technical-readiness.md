# Slack — 도입 전 기술 확인과 사용자 안내

**산출물:** PoC 환경 비교, 보안 설명, 초기 접속 및 CRM 연동 가이드의 공개용 재구성

고객이 도입을 결정하려면 업무 활용뿐 아니라 인증·권한·데이터 취급과 정식 운영으로의 전환 조건을 이해해야 합니다. 기술 설명 자료에서는 이 조건을 정리하고, 사용자 안내에서는 실제로 수행할 일을 짧은 단계로 나눴습니다.

## 1. PoC를 시작할 때 운영 전환까지 함께 확인

PoC 환경 비교 자료는 시험 비용과 함께, 이후 채널·앱·워크플로·데이터를 어떻게 처리할지 설명하는 구조입니다. 이를 공개용 검토표로 재구성했습니다.

| 고객과 확인할 질문 | 남길 결정 | 다음 단계에 미치는 영향 |
|---|---|---|
| 무엇을 검증할 것인가 | 대상 업무, 참여자, 시험 범위 | 필요한 환경과 기능의 범위 |
| 어떤 데이터를 사용할 것인가 | 시험 데이터와 실제 업무 데이터의 구분 | 접근·보존·종료 시 처리 조건 |
| 정식 도입 때 무엇을 이어갈 것인가 | 채널, 앱, Workflow, 이력별 유지·재구성 여부 | 재작업과 일정 산정 |
| 도입 여부를 언제 판단할 것인가 | 검토 시점과 필요한 결과 자료 | 종료·연장·운영 전환 계획 |
| 전환을 누가 맡을 것인가 | 고객 관리자, 컨설턴트, 공급사 담당 범위 | 인계와 후속 지원 범위 |

환경별 보존·이관 가능 여부는 계약과 실제 구성에서 확인합니다. 비교표의 목적은 환경 선택이 뒤의 일정과 운영 자산에 미치는 영향을 고객이 판단하도록 돕는 것입니다.

## 2. 보안 질문을 담당자와 확인 항목으로 연결

보안 설명 자료의 인증·접근, 데이터 보호, 정보 분리, AI, 감사 항목을 실무 질문으로 바꿨습니다. 아래 표는 협의 구조의 예시입니다.

| 검토 영역 | 고객에게 확인할 내용 | 함께 확인할 담당 역할 |
|---|---|---|
| 인증과 계정 | 회사 계정으로 접속하는 경로, 입사·이동·퇴사 시 처리 | 계정·인증 담당자, 플랫폼 관리자 |
| 접근 범위 | 조직·채널별 참여 대상, 외부 협업자, 관리자 위임 범위 | 업무 책임자, 플랫폼 관리자 |
| 데이터 취급 | 공유 가능한 자료, 보존 기준, 파일과 링크의 취급 | 정보보안, 문서 관리, 업무 담당자 |
| 기기와 네트워크 | 사내·재택·외부·모바일 이용 조건 | IT 운영, 정보보안 |
| AI·외부 앱 | 연결 데이터, 요청 권한, 승인 주체, 확인할 처리 조건 | 보안·앱 관리자, 공급사 |
| 감사와 운영 | 필요한 기록, 점검 주기, 예외·장애의 접수 경로 | 보안 운영, 플랫폼 관리자 |

기존 문서 보안과 협업 플랫폼의 역할도 함께 설명했습니다. 예를 들어 보호 문서를 파일로 공유할지 원본 시스템의 링크로 안내할지는, 정보의 등급과 고객의 운영 정책을 먼저 확인할 과제입니다.

## 3. 사용자의 상황에 맞춰 안내를 나누기

초기 접속 가이드에는 강지원이 작성자로 표시되어 있으며, 처음 초대받은 사용자·재접속 사용자·계정 복구가 필요한 사용자를 서로 다른 흐름으로 구성했습니다.

| 사용자 상황 | 문서에서 해결할 질문 | 안내 구성 |
|---|---|---|
| 처음 초대받음 | 어디서 시작하고 어떤 조직에 들어가는가 | 초대 확인 → 승인된 가입 경로 → 대상 조직 확인 |
| 다시 접속함 | 어떤 계정과 로그인 경로를 쓰는가 | 접속 위치 → 고객 환경에 맞는 인증 → 조직 선택 |
| 접속에 실패함 | 직접 확인할 것과 지원 요청할 것은 무엇인가 | 상황별 확인 → 승인된 복구 절차 → 지원 경로 |

한 단계에 하나의 행동을 배치하고, 화면·번호·화살표로 다음 동작을 찾도록 설계했습니다. 원본에는 고객별 화면을 넣을 자리가 남아 있어, 이 사례는 안내 구조와 문안의 작성 경험을 보여줍니다.

## 4. 연동 가이드에서 의존성과 확인 순서를 드러내기

Salesforce·Slack 연동 자료는 사전 조건, 양쪽 관리자 역할, 사용자 연결과 권한, 연결 확인, 문제 해결 순서로 구성했습니다. 이를 공개용 문서 틀로 정리하면 다음과 같습니다.

```text
목적: 이 연동으로 지원할 업무
선행 조건: 계정·환경·권한과 필요한 승인
담당 역할: 각 시스템의 관리자와 업무 확인 담당자
작업 순서: 요청 → 승인 → 설정 → 확인
확인 결과: 기대 동작, 실제 결과, 남은 문제
후속 조치: 담당자, 재확인 시점, 사용자 안내
```

이 구조는 기술팀에는 작업 순서를, 고객 담당자에게는 의사결정과 운영 준비 사항을 보여줍니다.

## 자료 근거와 범위

2025–2026년 PoC 환경 비교, 보안 개요, 초기 접속 가이드와 CRM 연동 자료의 설명 방식을 재구성했습니다. 초기 접속 가이드는 개인 작성 표시를 확인했고, 나머지는 담당 경력과 함께 보는 회사 업무 자료입니다. 이 페이지는 문서화·협의 설계 샘플이며, 현재 제품의 기능표나 고객 환경의 설정 완료 기록은 아닙니다.
